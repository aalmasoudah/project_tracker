# Phase 19: Telegram AI Executive Assistant

Status: Completed and verified locally on 2026-08-06.

## 1. Goal

Allow the deployment-configured CEO to ask bounded Arabic or English executive
questions in the existing private Telegram chat and receive concise, cited,
read-only answers generated by Groq from current application evidence.

## 2. Included Features

- Standalone natural-language questions about project and task risk, deadlines,
  blockers, progress, workload indicators, milestones, and approval bottlenecks.
- Deterministic local risk ranking before the provider call so the smallest,
  highest-value evidence set is used.
- Strict-schema Groq output using `openai/gpt-oss-120b` by default and the
  already approved 20B override when explicitly configured.
- Arabic/English language detection, cited Telegram-safe answers, bounded
  asynchronous processing, safe retries, idempotent message handling, audit,
  and protected retention.
- Signed n8n start/status calls using the existing CEO/chat, HMAC, timestamp,
  nonce, and replay-protection boundary.

## 3. Excluded Features

- Multi-turn memory, an unrestricted chatbot, arbitrary tools, web search,
  browsing, code execution, URLs, files, SQL, shell, or arbitrary HTTP.
- Creating, changing, approving, assigning, commenting on, or notifying about
  business records.
- Budgets, comments, uploaded-file contents, credentials, environment data,
  raw audit metadata, trainee/attendance records, contact details, or employee
  names in the AI evidence.
- Questions from any Telegram user or chat other than the configured CEO pair.

## 4. User Stories

- As the CEO, I can ask in Arabic which unfinished tasks are most likely to
  cause problems if they are not finished early.
- As the CEO, I can ask in English which projects need attention and why.
- As the CEO, I receive task/project codes beside factual findings so I can
  verify the answer in the application.
- As an operator, I can disable the conversational extension without disabling
  the existing fixed PDF commands or critical alerts.

## 5. Models

`ExecutiveAssistantRequest` stores a protected request lifecycle, the validated
standalone question, language, hashed Telegram message key, bounded cited
answer, provider/model/prompt version, safe usage metrics, timestamps, and a
safe failure code. It never stores the provider prompt, provider response
envelope, chain-of-thought, credentials, chat ID, or raw provider error.

## 6. Endpoints and n8n

- `POST /integrations/n8n/telegram/assistant/start/`
- `POST /integrations/n8n/telegram/assistant/status/`
- Non-command Telegram text routes to the assistant branch.
- `/help`, `/tasks`, `/overdue`, and `/attendance` retain their Phase 16
  behavior. Unknown slash commands return help and are never AI prompts.

## 7. Permissions

Only the exact configured active CEO username/chat pair with the new
`ask_executiveassistant` permission may create or retrieve an answer. Django
rechecks identity, role, permission, chat binding, and current source visibility
when the request is accepted, processed, and read.

## 8. Validation and Limits

- Trimmed question length is 3 through 500 Unicode characters.
- One Telegram message ID is accepted idempotently once per configured chat.
- Control characters, URLs, credential-like strings, secret requests, prompt
  extraction/injection, personal-data requests, and unsupported domains fail
  closed before the provider call.
- A question must contain an approved Arabic or English executive-work topic.
- Evidence is capped at 40 ranked task/project/approval sources and provider
  output at 1,200 tokens. Telegram text is capped below its 4,096-character
  limit.
- The assistant has a separate configurable daily limit, stale timeout, and
  feature flag.

## 9. Evidence and Answer Rules

- Select only records currently visible to the CEO and exclude archived,
  cancelled, completed, or otherwise non-actionable task contexts.
- Rank tasks locally using stable status, criticality, overdue/due-soon state,
  and approval bottlenecks. The model may explain but may not invent the rank.
- Database and question strings are untrusted data. The model receives no
  tools and cannot expand its evidence or scope.
- Every factual finding and recommended next step must cite one or more
  allowlisted source references. Django resolves citations to safe task,
  project, milestone, or approval labels before Telegram delivery.
- Unsupported questions receive a fixed localized response without a provider
  call. Each question is standalone; no conversational memory is retained.

## 10. Migration

- Add the protected `ExecutiveAssistantRequest` model, lifecycle constraints,
  indexes, idempotency uniqueness, and CEO-only permissions.

## 11. Required Tests

- Arabic and English accepted questions and localized responses.
- Risk evidence ordering, bounds, exclusions, and citation validation.
- Wrong chat/role, inactive or revoked CEO, bad HMAC, stale timestamp, replay,
  forged request ID, duplicate message, and daily/token/body limits.
- Prompt injection, secret/credential, URL, personal-data, attendance, shell,
  SQL, and unrelated questions rejected before Groq.
- Provider timeout/retry, invalid schema/citation, stale recovery, idempotent
  completion, and audit/log privacy.
- n8n workflow structure, credential absence, question routing, polling,
  response length, existing-command regression, and Telegram-safe output.

## 12. Manual Verification

1. Ask an Arabic task-risk question from the configured CEO chat.
2. Verify the answer cites known fictional KAU/KSU/KKU records.
3. Ask an English executive-status question and verify English output.
4. Send an injection/secret request and verify fixed rejection without Groq.
5. Send the same Telegram update twice and verify one stored request.
6. Send from another chat and verify no response or source-record discovery.
7. Confirm `/tasks`, `/overdue`, `/attendance`, critical alerts, and `/help`
   still work.

## 13. Acceptance Criteria

- The example Arabic risk question returns a concise, current, cited answer.
- At least one task-risk finding is based on deterministic local ranking and
  strict provider output validation.
- No question can expand the approved source fields, recipient, tools, or
  write authority.
- Arabic/English, retry/idempotency, authorization, injection, privacy, n8n,
  and regression tests pass with the full repository quality gate.

## 14. Rollback

Set `EXECUTIVE_ASSISTANT_ENABLED=false` and republish the prior n8n workflow.
Preserve protected request/audit evidence. Fixed reports, alerts, project AI
briefings, and the project agent remain available.
